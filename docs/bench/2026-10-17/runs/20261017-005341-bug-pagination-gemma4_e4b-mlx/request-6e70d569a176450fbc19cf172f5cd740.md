## Result

The current logic incorrectly decrements the starting index by 1 when `number > 1`, causing the start of a new page to include the last element of the previous page.

## Reasoning

The user is reporting a bug in the pagination logic. Specifically, they say "When I look at the second page of results, the first thing on it is something I already saw at the end of page one."

This suggests that the function `pager.page` might be calculating the starting index incorrectly, leading to overlap between the end of one page and the start of the next.

I need to examine `pager.py` and the related test file `tests/test_pager.py` to understand the current implementation and verify the issue. First, I will read `pager.py`.The current implementation of `page` in `pager.py` is:
```python
def page(items, number, size):
    """The items on page `number` (counting from 1), `size` per page."""
    start = (number - 1) * size - 1 if number > 1 else 0
    return items[start:start + size]
```

Let's trace this logic for the second page (`number=2`).
If `number=2`, then `number > 1` is True.
`start = (2 - 1) * size - 1 = 1 * size - 1 = size - 1`.

If `items` has length $L$, and `size` is the page size.
Page 1 (`number=1`):
`start = 0` (because `0 > 1` is False).
Returns `items[0:size]`. This is correct.

Page 2 (`number=2`):
`start = size - 1`.
Returns `items[size - 1 : size - 1 + size]`, which is `items[size - 1 : 2*size - 1]`.

If the items were 1 to 100, and `size=10`.
Page 1: `items[0:10]`, i.e., items 1-10. (Indices 0-9).
Page 2: `items[10 - 1 : 2*10 - 1]`, i.e., `items[9:19]`.
The start index is 9. Item at index 9 is the 10th item (the last item of P1). The next expected item is item 11 (index 10).

By setting `start = size - 1` for the second page, we are causing the overlap. The starting index of page $N$ should be $(N-1) \times \text{size}$.

The fix should be:
```python
def page(items, number, size):
    """The items on page `number` (counting from 1), `size` per page."""
    start = (number - 1) * size
    return items[start:start + size]
```
This simplifies the logic and handles `number=1` correctly (start = 0).
