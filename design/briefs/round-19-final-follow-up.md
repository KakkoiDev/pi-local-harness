# Round 19 final follow-up decisions

21 October 2026. Follow-up to design commit 01070dd1. The owner previously delegated selecting the best recommendations and closing design gaps. These decisions complete that direction; they authorize design work, not claims of working backend features. Read round-19.md and the round 19 handoff first.

1. Unsaved drafts: show the persistent Unsaved state and register the browser's native leave-page warning while unsaved changes exist. Do not promise protection against browser termination, crashes or mobile OS eviction; beforeunload is best effort. Persist to the host when available; browser persistent draft storage remains excluded. Failed navigation must not erase the in-memory draft.
2. Online save failure: show Not saved with Retry, preserve the buffer, and use revision-checked retry. Newer remote data must yield a preserved conflict, never overwrite either version. Prevent duplicate simultaneous saves; save completion for an old revision must not mark newer text saved.
3. Deletion in another window: stop editing/sending and display read-only conversation Trash detail. Preserve any unsaved local draft as a recoverable conflict associated with the trashed conversation. Never submit late saves to resurrect it. Restore explicitly, revalidate access, and never resume requests automatically.
4. Owner removes a project: retain its conversation Trash under its stable project ID with removal metadata. Explain what is retained in confirmation. Do not move or delete the user's project directory or data as part of unregistering it. Re-registering the same identity can reconnect retained history; a reused name/path is not proof of identity. Access revocation still withholds protected data.
5. Disconnected Overview: retain the explicit selection, show it as stale, disable New Task with the reason and revalidate on reconnect and submission. Removal or loss of access clears it. Never imply that cached health is current.
6. Providers: display the configured non-secret provider name with a safe generic fallback. Do not show endpoint URLs, credentials or query parameters in status or accessible names. Treat configured names as text, not markup.
7. Phone conversation title: use the row below the PhoneBar with the conversation-specific menu. Define truncation and an accessible full title; honor generated-title redaction. Do not move conversation commands back into Agent or view menus.
8. Recorder limits: maximum 500 normalized events per flow, 50 events per batch, and 64 KiB per encoded HTTP body. Host checks all limits before storage. Reject oversized batches without partial writes; show capture failure/coverage gap. On a full flow, stop accepting further events into it and mark it truncated; do not silently evict early events or create unlimited replacement flows. A new session/reproduction may start a new flow. Normal event batching does not create flows. Keep the established 20-flow/7-day limit per bucket. Implementation may use smaller transport chunks, never relax server limits without a documented change.
9. Phone opt-in: use the existing Settings surface plus a one-time dismissible notice. WorkStation recording remains off until explicit Enable; Not Now leaves normal app usage available. Preview's separately approved default remains visible and independently controllable. Do not capture the opt-in interaction before consent.
10. Identity: recording choice/history is per authenticated person on the host. Anonymous/shared-secret sessions must not claim to distinguish people; use a clearly labelled shared local profile with WorkStation recording off until enabled for that profile. No new multi-user account system is implied. A profile/session switch closes capture sessions and clears client buffers; never transfer another person's events or preference.
11. Test drafts: offer Save as Test Draft for Preview-only flows in this release. Mixed or WorkStation-only flows remain inspectable/attachable but cannot imply a supported generated test. Test drafts require assertions and ordinary phase gates; never replay actions automatically or treat capture as a passing test.
12. Dark theme: fix missing selection tokens within the appropriate dark wrapper used by design boards. Verify light and dark rendering without changing unrelated application styles. Fix duplicate IDs in the six touched addendum boards as part of final design QA; update references consistently.
13. Copy: use Restore the conversation first. and Conversation restored. Define consistent Japanese alongside existing restore vocabulary; disclose that native-speaker review has not occurred. Restore errors must preserve the Trash item and any draft.
14. Canvas capacity: create a second canvas for round 19 onward, retaining the original canvas and its history unchanged. Keep all boards and manifests in the repository, with an index documenting which canvas contains each round. Do not claim the first canvas is synchronized with round 19. No permanent deletion, archive pruning or new paid service is authorized.
15. Comments: @ mentions remain deferred in comment composers; do not expand this release's scope.
