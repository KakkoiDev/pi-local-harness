Sharing while offline.

Sync queue

Cited as source 1 · lines 12–40

Every edit made while offline goes into a queue in the browser (IndexedDB), in the order it was made.

When the connection returns, flushQueue() sends the queue one edit at a time. An edit leaves the queue only when the server confirms it.

  • A reload keeps the queue.
  • Two tabs share one queue; only one tab sends.
  • After 3 failed tries an edit waits for the next connection.

Limits

  • The queue holds up to 500 edits.
  • Attachments wait until the connection returns; they are not queued.

Decided 8 Oct; task 4 in ROADMAP.md.

Conflicts

The newer edit wins; the older one is kept as a copy.
