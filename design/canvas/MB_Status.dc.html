Menu bar status — a button that still reads as status

Working

Reads as status: no frame. Hourglass while something runs; the › shows on hover.

Waiting only

Queued, nothing running yet (the model is loading or the previous request is finishing). Clock glyph.

Idle

Nothing running or waiting. Still a button.

Hover

1px ink frame and › say it opens Activity.

Pressed

Inverted while the pointer is down, like a menu title. Release opens Activity · All Projects (⌘3).

Attention · Failed

A request failed, stopped or was interrupted. The real word leads; with two or more: “2 need attention”. Attention wins over Working until Activity is opened, then the button shows Working again.

Attention · Stopped

Attention · Interrupted

Opening Activity (any way: this button, ⌘3, the Agent row, the Window menu) clears attention. Connection interrupted: the button opens nothing and Reconnect follows it.

Agent section

A ListGroup under Projects, titled Agent, count “All projects”. Two rows, both app-level windows: Activity (⌘3) and Gate (⌘4). The meta is the live count, updated with the menu bar status.

Activity: “1 running · 1 waiting” with the hourglass; “1 waiting” with the clock; “Nothing running” when idle; “1 needs attention” with the caution glyph. Gate: “12 checks · 1 blocked” with the stop glyph; “12 checks today”.

The open window’s row is selected (aria-current="page"). A project row opens that project’s Chat.
