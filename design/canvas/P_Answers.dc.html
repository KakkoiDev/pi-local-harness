Beside or a view?

Beside, as its own window to the right of the chat, while the chat keeps at least 480 px. Under that (a narrow window, a small laptop with the Project window open), Preview becomes a third segment: Chat ⌘1 · Work ⌘2 · Preview ⌥⌘P. ⌘3 and ⌘4 are taken by Activity and Gate.

The toggle in the chat’s info bar (Preview, pressed when open) and Window → Preview ⌥⌘P are the same command. The Preview also sits beside Work.

Phone: a view in the view menu (Chat · Work · Preview), not a sheet. The app needs the whole 390 px and its own bottom sheets; a sheet over the chat would cut its top and fight its gestures. Open App opens it in Safari, where Add to Home Screen installs it.

Who starts the app?

The workbench, when the Preview is shown. The first time a project has an app (Pi’s answer leaves a run command that answers), the Preview opens beside the chat by itself, once; after that it opens as the person left it.

Not before it is opened: at about 1.5 s once installed (task 202) there is nothing to win by starting early, and an app nobody looks at should not run beside the model. It stops when the project is closed or plh quits. One Stop / Start button in the Preview’s foot, not a pair: the state word beside it says which is true.

Reloads come from the app’s own --reload; the note line only says so.

Undo wording

Undo This Request…. Undo is the word the Mac already teaches; “Take This Back” is friendlier but new, and reads like withdrawing words. The alert names the request by the first line of its plain words, says what goes back, says the notes (data) are not touched, and Cancel is the default.

When it overlaps newer requests: nothing changes; a Note alert names the later request and the file, and offers Ask Pi Instead (default), which sends “Take out the Delete buttons and keep the newest-first order” as a request. Never a half-applied revert, never a merge conflict on screen.

The undo is a new commit with its own row (↶ Undone) and Redo Request…; the original row says “undone at 14:40”, its Undo disabled (the built “already undone” case never shows).

The built messages are right for the terminal. In the web the alert splits each one: the title says what did not happen, the detail says why and “Nothing was changed.”, and the advice becomes a button: “Ask Pi to take that change out by hand” is Ask Pi Instead; “Keep or discard those changes first” is Save Them, Then Undo. Repo: name the later request in the overlap message.

Where the lines go

A separate quiet row under the answer, not inside the bubble. The bubble is Pi talking; the row is the record of a change (one commit): it exists only when files changed, it carries the change’s buttons, and the harness can check it. Its plain words are written by Pi for the task file’s “For the person” section, so Activity and the Undo alert can quote them.

Move the G-012 line there too: “! Not verified” becomes the row’s state instead of a bold paragraph appended to the answer.

The lesson line sits at the bottom of the same row behind a dotted rule: at most one, Hide removes it, Settings → “Show lessons” turns them off. No × buttons.

New Project… kinds

Three radio choices with one line each, in that order; Web app the default, as proposed. The deciding question sits under them as help, starting “Not sure?”, so a person who knows skips it.

The line above the buttons changes with the choice and says what gets made, so Create is never a surprise. Empty folder keeps today’s line.

A new System 1 Radio (14px circle, 8px dot) replaces the browser’s radio here and in Settings.

The Preview is the same for both app kinds; a no-server app is served as files, so Starting is near-instant and Stop only stops serving.

Japanese

Every bar wraps (flex-wrap) and every button sizes to its label; no label has a fixed width. The longest Japanese labels on these boards are 「この依頼を取り消す…」 and 「ブラウザで開く」; at 480 px the Preview foot wraps its buttons to a second line before anything clips.

The app’s language switch (English · 日本語) is the app’s, not the workbench’s; they are set separately. Mixed Japanese and English in one line use the system font’s Japanese (Hiragino Sans on the Mac).
