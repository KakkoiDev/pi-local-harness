# 344: Keep generated interpreter caches out of request verification

Kind: code
No scenarios: internal change inventory; existing plan/build/check-in browser stories cover the affected workflow.

Found while running the required curator browser regression suites: Python bytecode generated by the test runner incorrectly counted as out-of-scope work in a scratch project without a gitignore.

- [x] Red: untracked interpreter bytecode appears in changed paths.
- [x] Exclude only untracked CPython cache filenames; preserve tracked caches and source files in cache folders.
- [x] Green: protocol unit tests and existing plan/build browser stories pass.

## For the person
Running tests will not make a task fail verification merely because Python created its cache.
Tried it: two cache regression tests and all existing plan/build, Undo/Redo and golden-journey browser stories.
