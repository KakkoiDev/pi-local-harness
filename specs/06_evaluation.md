# Spec: The Evaluation Framework (The Learning Loop)

## 1. Overview
The Evaluation Framework is designed to move from static scoring to dynamic, repeatable regression testing. It utilizes a "Capture and Replay" workflow to turn operational errors into "Golden Datasets" for continuous model refinement.

## 2. The Lifecycle

### Phase 1: Capture (The Intelligence Engine)
When a user or the system identifies a "Ground Truth" event (a successful or failed task that is highly relevant), the system creates an `EvaluationCase`.
- **Detection**: An operator triggers `laya capture <run_id>`.
- **Extraction**: The system extracts the `input_state` (the state at the start of that run), the `actual_trace` (the recorded audit logs), and the user-provided `gold_truth` (what *should* have happened).
- **Storage**: The case is saved to `tests/laya_eval/datasets/`.

### Phase 2: Replay (The Regression Test)
A regression test re-runs old tasks in a controlled, isolated "Sanitized Environment" to ensure that changes to the Agent or the Judge do not violate historic "Ground Truth" outcomes.
- **Injection**: The `input_state` is injected into the Actor.
- **Execution**: The Actor runs the task in the current environment (new code, new policy).
- **Comparison**: The resulting `actual_trace` is compared against the `gold_truth`.

### Phase 3: Analysis (The Report)
The scoring engine assesses the match between the actual result and the gold truth using three metrics:
1. **Outcome Accuracy**: Did the final verdict match high-level intent (e.g., ALLOW vs BLOCK)?
2. **Process Compliance**: Did the agent follow the correct order of operations?
3. **Information Fidelity**: Did the agent's reasoning match the observed evidence?

## 3. The Dataset Taxonomy

| Type | Origin | Purpose |
|---|---|---|
| **`true_event`** | Captured from real-world operational logs. | Represents the "Real World" edge cases and human-verified successes. |
| **`synthetic`** | Generated by LLMs via template prompting. | Represents "Edge Case" permutations and high-variance scenarios (e.g., adversarial payloads). |

## 4. Automated Regression (The CI Gate)
During the CI/CD pipeline, the system runs the `laya_regression_test` command.
- **Fail Case**: If any `EvaluationCase` fails to match its `gold_truth` (Outcome mismatch or Policy error), the build is **FAILED**.
- **Drift Detection**: If a previously passing test begins to fail due to an update in the LLM or policy version, the system flags the "Regression" for manual review.
